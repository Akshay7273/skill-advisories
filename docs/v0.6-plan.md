# v0.6 plan: dependable at ecosystem scale

v0.6 is an infrastructure and adoption milestone. It will not ship merely
because a version number or a date has been reached. The release must show that
the advisory service is bounded under hostile input, observable in production,
operable by maintainers, and straightforward for other projects to adopt.

## Release outcomes

### 1. Bounded scanning

- Hash files as streams instead of loading whole files into memory.
- Bound artifact and file concurrency with deterministic output.
- Enforce configurable per-file, per-artifact, and total scan budgets.
- Report every skipped file and exhausted budget as structured scan metadata.
- Preserve the existing API defaults and fail-safe matching behavior.

### 2. Reproducible evidence

- Publish a synthetic benchmark generator that contains no third-party code.
- Measure exact lookup at 100,000 artifact identities and filesystem scanning at
  10,000 generated artifacts.
- Record wall time, throughput, peak resident memory, runtime, OS, and corpus
  parameters as machine-readable JSON.
- Run a smaller regression budget in CI; publish full benchmark results for
  release candidates without claiming results from unexecuted environments.

### 3. Verifiable operations

- Publish machine-readable feed age, validation, checksum, and release status.
- Add tested runbooks for advisory triage, correction, withdrawal, compromised
  releases, and last-known-good feed recovery.
- Add automated reference, schema, duplicate, and freshness checks.
- Produce signed npm provenance and feed attestations from the release workflow.

### 4. Adoption and contribution

- Ship maintained examples for Claude Code, OpenClaw, generic MCP clients, and
  GitHub Actions.
- Publish a compatibility policy and integration contract.
- Create scoped `good first issue` work with tests and acceptance criteria.
- Document downstream integrations and public user reports in an adoption log;
  never infer dependents from downloads alone.
- Obtain at least one independently maintained integration or documented pilot
  before declaring the milestone complete.

## Release gates

v0.6.0 requires all of the following:

1. Cross-platform CI, protocol tests, package smoke tests, and feed compilation
   are green at the release commit.
2. Resource limits are covered by regression tests, including oversized,
   unreadable, symlink, and budget-exhaustion cases.
3. Benchmark results are reproducible from a documented command and identify
   the exact commit and environment.
4. Operational status and recovery documentation are public.
5. At least three supported integration paths have runnable examples.
6. At least one downstream adopter or pilot can be cited publicly.

If the adoption gate is not met, the code may be published as a prerelease, but
the stable milestone remains open.

## Non-goals

- Inflating commits, stars, downloads, dependents, or contributor counts.
- Treating absence from the advisory feed as proof that an artifact is safe.
- Uploading proprietary or harvested third-party source into benchmark corpora.
- Claiming compatibility with an ecosystem that has no maintained test or
  runnable example.
